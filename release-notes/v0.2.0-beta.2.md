# WhatsApp Admin Studio v0.2.0-beta.2

This beta focuses on the first real Windows troubleshooting cycle: Owner Claim now follows the WhatsApp connection state, and Studio creates a persistent diagnostic log that can be shared after reproducing a problem.

## Fixed and improved

- Owner claim codes are generated only after WhatsApp reaches **Connected**.
- Studio shows both the six-digit value and the exact `!claim 123456` command.
- Copy and renewal actions stay disabled until WhatsApp is ready.
- A 45-second startup timeout offers **Reset session and show new QR** when WhatsApp provides neither QR nor ready state.
- Persistent diagnostic log at `%APPDATA%\WhatsApp Admin Studio\logs\admin-studio.log`.
- **Settings → Diagnostic logs → Open logs folder** opens the exact file location.
- Logs rotate at approximately 5 MB and keep one previous file.
- Claim codes, QR payloads, and incoming message bodies are redacted.
- Chromium DevTools and SQLite experimental warnings are recorded as runtime information instead of fatal errors.
- The log records Windows Authenticode status, signer, and timestamp presence.
- Arabic and English OCR remain included.

## Test sequence

1. Install this beta over the previous version.
2. Open Studio and wait for QR or Connected state.
3. If startup times out, use **Reset session and show new QR**.
4. After Connected, send the complete command shown by Studio, including `!claim`.
5. Test `!ping`, `!status`, Restart, and one Arabic/English OCR image.
6. If anything fails, close Studio and send `admin-studio.log` from the Settings shortcut.

## Signing

This beta records its Authenticode status in the diagnostic log. It remains unsigned until a trusted certificate or signing-service account is connected to GitHub Actions, so Windows SmartScreen may display a warning.
